# ✂️ Editor — 파일 경로의 문제일 수 있으므로, 해당 동영상을 만들 때 사용했던 원본 소스 에셋과 최종 렌더링 파일 전체를 검토해주세요. 영상 자체가 손상(corrupted)되었는지, 아니면 단순히 경로 문제인지를 판단하여 보고해주세요.

✂️ Editor: 작업 시작합니다.

CEO 지시사항을 바탕으로, 단순 경로 문제와 파일 손상(Corruption) 문제를 구분하여 최종 진단 프로세스를 수행합니다. 영상의 최종 아웃풋을 신뢰성 있게 확보하기 위해, 원본 소스 에셋부터 최종 렌더링까지의 '데이터 무결성(Data Integrity)'을 최우선으로 검증해야 합니다.

---

### 🔍 영상 무결성 진단 및 보고서 (Diagnostic Report)

#### 1. 📁 진단 목표 및 범위
| 구분 | 진단 목표 | 확인 항목 | 담당 에이전트 |
| :--- | :--- | :--- | :--- |
| **접근성** | 파일이 시스템에 존재하는가? (Path Issue) | 권한(R/W), 경로 인코딩, 물리적 존재 여부 | 💻 Developer (스크립트 실행) |
| **무결성** | 파일 내용 자체가 손상되지 않았는가? (Corruption) | 코덱 스택 오류, 비트 스트림 손상, 프레임 누락 | ✂️ Editor (전문 검토) |
| **일관성** | 원본 소스에서 최종 아웃풋까지의 변환 과정이 정상이었는가? | 렌더링 설정(Codec, Bitrate) 일치 여부 | 🎨 Designer/✂️ Editor (검토) |

#### 2. ⚙️ Step 1: 파일 접근성 진단 (Developer Action Required)
*   **Action:** Developer가 제공한 `파일 접근성 진단 스크립트`를 **반드시** 최종 렌더링 파일 경로에 대해 실행하고, 그 결과를 전체 보고해야 합니다.
*   **진단 초점:** 스크립트 결과 중 `[PERMISSION]`과 `[SIZE]` 결과를 중점적으로 확인합니다.
    *   **결과 1 (경로 문제):** 만약 스크립트가 `❌ [ERROR] 파일이 존재하지 않습니다.` 또는 `[ERROR] 접근 거부`를 반환한다면, 이는 **명백한 경로/권한 문제**입니다. (Solution: 경로 재설정 또는 권한 부여)
    *   **결과 2 (무결성 의심):** 만약 모든 체크가 `✅ [OK]`로 나오지만, 여전히 플레이어가 인코딩 오류를 띄운다면, 이는 **파일 무결성 문제**로 넘어갑니다.

#### 3. 💾 Step 2: 파일 무결성 진단 (Editor Expert Review)
*   **진단 방식:** 최종 렌더링 파일을 전문 코덱 분석 툴(예: MediaInfo, FFprobe)을 사용해 내부 구조를 검사합니다.
*   **핵심 검토 포인트:**
    1.  **Codec Stack 확인:** 최종 파일의 코덱(Codec)과 컨테이너(Container)가 **[H.264 또는 ProRes]** 표준을 준수하는지 확인합니다. (만약 비표준 코덱이 사용되었다면, 플레이어 호환성 문제가 발생합니다.)
    2.  **프레임 무결성 (Temporal Integrity):** 영상의 시작 프레임(Keyframe)과 끝 프레임이 정상적으로 연결되었는지, 중간에 프레임 건너뛰기(Skipping)가 발생했는지 검토합니다.
    3.  **Metadata 오류:** 파일에 포함된 메타데이터(시간 정보, 오디오/비디오 싱크 정보)에 오류가 있는지 확인합니다.

#### 4. 🛠️ Step 3: 문제 유형별 최종 해결 방안 (Action Plan)

| 진단 결과 | 원인 판단 | 해결책 (에이전트 할당) |
| :--- | :--- | :--- |
| **A. 경로/권한 문제** | 시스템 접근 실패 (가장 흔함) | 💻 Developer가 권한을 재설정하고, **파일을 압축(ZIP)하여 전달**받아 재검증. |
| **B. 코덱/호환성 문제** | 플레이어 호환성 실패 | ✂️ Editor가 **[H.264, 4K, 30fps]** 표준으로 재인코딩(Re-encode) 지시. (가장 확실한 방법) |
| **C. 데이터 손상 문제** | 렌더링/처리 과정에서 데이터 손실 | 🎨 Designer가 원본 소스 에셋과 **최종 스크립트(컷 구성, 타이밍)를 기반으로 렌더링 프로세스를 처음부터 재수행**하도록 지시. |
