# 🚨 Git Push 에러(`src refspec main does not match any`) 대응 매뉴얼

본 문서는 `git push` 실패 시 사용자가 자신의 상황을 즉시 판단하고, 터미널에 복사·붙여넣기 하여 문제를 해결할 수 있도록 설계되었습니다.

## 🔍 에러의 핵심 의미
**"로컬 저장소에 보낼 데이터(커밋)가 없거나, 보낼 대상(브랜치 이름)을 찾을 수 없음"**

---

## 🛠 상황별 즉시 실행 가이드

### [상황 1] 저장소를 막 만들었거나, `git commit`을 한 번도 안 한 경우 (가장 빈번)
*   **증상:** `git add`는 했지만, 확정(commit)된 데이터가 없음.
*   **즉시 실행 명령어:**
    ```bash
    git add .
    git 1commit -m "initial commit"
    git push origin main
    ```

### [상황 2] 로컬 브랜치 이름은 `master`인데, 원격은 `main`을 요구하는 경우
*   **증상:** 로컬과 원격의 브랜치 명칭이 불일치함.
*   **즉시 실행 명령어:**
    ```bash
    # 1. 현재 브랜치 이름을 main으로 강제 변경
    git branch -M main

    # 2. 변경된 브랜치를 원격에 연결하며 푸시
    git push -u origin main
    ```

### [상황 3] 원격 저장소에 이미 다른 파일(README 등)이 있어 충돌하는 경우
*   **증상:** `failed to push some refs` 에러와 함께 원격의 변경 사항을 가져오라고 함.
*   **즉시 실행 명령어:**
    ```bash
    # 1. 원격의 변경 사항을 먼저 로컬로 가져와 합침
    git pull origin main --rebase

    # 2. 다시 푸시 시도
    git push origin main
    ```

## 💡 요약 체크리스트 (복사 전 확인)

| 단계 | 확인 사항 | 실행 명령어 |
| :--- | :--- | :--- |
| **1단계** | 커밋 내역이 있는가? | `git log` (내역이 없으면 **상황 1**로) |
| **2단계** | 현재 브랜치 이름이 `main`인가? | `git branch` (master라면 **상황 2**로) |
| **3단계** | 원격과 동기화가 되었는가? | `git pull origin main` (에러 나면 **상황 3**으로) |
